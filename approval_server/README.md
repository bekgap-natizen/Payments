# ВОЛМАКС Payments 0.7.0 — пилот мобильного согласования

Это отдельный серверный пилот, а не обновление установленной версии 0.6.11.
Не переносите реальные ведомости в GitHub и не открывайте пилот публично без проверки.
Сервер не осуществляет банковских переводов.

## Сценарий
- Бухгалтер входит на защищённый сайт, открывает рабочее место, загружает 1С,
  распределяет суммы по существующим правилам 0.6.11 и нажимает «На согласование».
- Коммерческий директор видит реестр и историю; генеральный директор может
  утвердить его или вернуть бухгалтеру с комментарием. Ровно один аккаунт директора.
- При возврате новая отправка создаёт новую неизменяемую версию на ту же дату.
  На дату допускается один действующий реестр. Бухгалтер исправляет исходный план
  в своём браузере. Остаток не перераспределяется на телефоне.
- Только бухгалтер скачивает утверждённый Excel и отправляет утверждённый реестр
  через локальный Windows Mail Server. История различает утверждение и отправку
  письма; результат SMTP сообщается клиентом, не доказывает банковский перевод.
- Даты, организации и поставщики доступны в фильтрах истории. Сумма истории
  учитывает финальные утверждённые версии без двойного счёта возвращённых.

## Развёртывание (пилотный сервер, отдельный HTTPS origin)
1. Распаковать пакет или получить ветку mobile-approval-070. Установить Docker Compose.
2. Скопировать approval_server/env.example в approval_server/.env. Указать выделенный
   HTTPS origin (пример только шаблон). Не публиковать .env и содержимое /data.
3. В каталоге approval_server выполнить docker compose -f compose.yml up -d --build web.
   Веб-порт слушает только 127.0.0.1:8080 хоста; настроить отдельный DNS и HTTPS
   reverse proxy к этому порту. Нужен сертификат, доступный iPhone и Android.
   Не использовать открытый HTTP для финансовых данных.
4. Создать реальные учётные записи локально на сервере:
   docker compose -f compose.yml exec web flask --app approval_server.app:create_app user LOGIN accountant
   Аналогично commercial и director. Пароли вводятся интерактивно; минимум 12 символов.
   Повтор команды меняет пароль и сбрасывает сессии/подписки. Не добавлять реальные
   имена, пароли, реестры или ключи в GitHub.
5. Для Web Push:
   docker compose -f compose.yml exec web python -m approval_server.generate_vapid
   Сохранить вывод в локальный .env, указать PAYMENTS_VAPID_SUBJECT, затем выполнить
   docker compose -f compose.yml --profile push up -d --build --force-recreate.
   Работает один worker. Подключить уведомления в интерфейсе на каждом устройстве.
   iOS/iPadOS 16.4+: Safari → «На экран Домой», открыть установленное веб-приложение,
   нажать «Уведомления» и разрешить их. Android: установить из Chrome, разрешить push.
   Без отдельного согласия уведомление не показывает финансовые данные на экране
   блокировки. С согласия показывается сокращённая сводка; полный список — внутри.
6. Для почты на Windows: требуется существующий Mail Server 0.6.7+ и разрешённый
   origin нового портала. На отдельном тестовом компьютере задать переменную
   VOLMAX_APPBOX_ORIGIN равной точному HTTPS origin портала и запустить BAT в этой
   среде (или перезапустить сессию Windows после задания пользовательской переменной).
   Это заменяет разрешённый обычный origin для данной копии Mail Server; не менять
   рабочую установку 0.6.11 без проверки. Установить/сохранить пароль приложения Яндекса
   в Windows Credential Manager, выполнить привязку по коду.
   При ошибке отправки проверить «Отправленные», затем отметить найденное письмо
   или разрешить повтор. Автоматической повторной отправки нет.
7. На тесте: использовать вымышленный файл 1С и отдельную почтовую среду;
   проверить мобильный вход, роли, возврат, историю, пуш и SMTP.
   Не посылать реальный реестр четырём рабочим адресатам до согласования пилота.

## Ограничения перед эксплуатацией
- Исходная ведомость, настройки и черновики остаются в локальном хранилище
  компьютера бухгалтера; сервер синхронизирует отправленные реестры и историю.
  При смене браузера потребуется повторно загрузить 1С. Старые реестры 0.6.11
  не мигрируют автоматически.
- Сервис использует HTTPS, хешированные пароли, серверные сессии, CSRF-защиту,
  ограничения ролей и транзакции SQLite. Перед реальными данными необходимы
  проверка конфигурации, резервное копирование тома /data с SQLite backup API,
  политика доступа, отзыв доступа сотрудникам и независимая проверка безопасности.
- Проверить реальный браузер AppBox отдельно. Пилот работает в отдельном
  защищённом веб-приложении, а не во вложенном фрейме AppBox.
- Push и реальная почта зависят от инфраструктуры, разрешений устройства и
  доступности сервисов. Автотесты не являются подтверждением реальной доставки.

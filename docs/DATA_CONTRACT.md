# Контракт данных 1С и правила расчёта

## Поддерживаемая выгрузка

Excel `.xlsx`, лист `TDSheet`, группировка строк `outlineLevel`:
- `0` — организация;
- `1` — поставщик;
- `2` — документ.

В ячейках: `B` — наименование уровня, `C` — номер/дата входящего документа, `D/E` — обороты, `F` — конечный остаток.
Суммировать вместе `F` организации, поставщика и документов **запрещено**, иначе появится двойной/тройной учёт.

Итоговый баланс поставщика берётся из строки уровня `1`, детали уровня `2` — для расшифровки и контроля. Отрицательное сальдо обычно означает задолженность, положительное — аванс/переплату; знак проверяется по конкретной конфигурации 1С.

### Известные ограничения

- Некоторые документы без даты входящего счета.
- Групповые остатки могут не сходиться с суммой деталей; такие суммы помечаются как расхождения.
- Оплаты и корректировки уже учтены в конечном сальдо и не должны вычитаться повторно.
- Нет полной связи «платёж → погашаемый документ»: **долг на уровне накладной не установлен достоверно** без дополнительного регистра 1С.

### Правила утверждения

Не предлагать оплату больше нетто-долга, выделять расхождения в отдельный список. Не считать неподтверждённые значения точными. Не отправлять платёж в банк. После загрузки новой ведомости не учитывать отметку об оплате предыдущего среза второй раз.

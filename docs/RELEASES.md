# Скачать и запустить ВОЛМАКС — Платежи поставщикам

**[Открыть список готовых версий (GitHub Releases)](https://github.com/bekgap-natizen/Payments/releases)**

## Что скачивать

На странице Releases выберите нужную версию. Первые версии помечены **Pre-release**: это тестовый прототип, не промышленная платёжная система.

Разверните **Assets** и скачайте именно **`VOLMAX-Payments-Offline.zip`**. Файлы `Source code (zip)` и `Source code (tar.gz)` содержат исходный код и **не предназначены для запуска без сборки**.

## Запуск без установки

1. Скачайте ZIP из **Assets**.
2. **Распакуйте весь архив** в отдельную папку. Не запускайте HTML прямо внутри окна архива.
3. Откройте файл **`index.html`** в актуальном Chrome или Edge.
4. В приложении нажмите нижний пункт меню **«Обновить данные 1С»**, выберите файл ведомости XLSX и дату **бухгалтерского среза**.
5. Выберите активных поставщиков, настройте отсрочку; в разделе платежей вручную введите суммы и выгрузите Excel.

**Node.js, npm и интернет для работы скачанного пакета не требуются.** Файлы `assets/` должны лежать рядом с `index.html`.

### Если локальное хранилище заблокировано

Некоторые браузеры ограничивают работу IndexedDB при открытии `file://`. Используйте локальный HTTP-сервер, если установлен Python:

```bash
cd "папка_с_распакованным_архивом"
python -m http.server 8080
```

Затем откройте в этом же компьютере <http://localhost:8080/>. **Не предоставляйте доступ к серверу из общей сети или интернета.**

Данные сохраняются в браузере **локально**, не отправляются в GitHub. Переход с `file://` на `localhost` или в другой браузер создаёт отдельное локальное хранилище. Автоматического переноса и резервного копирования пока нет.

## Ограничения финансовой модели

- Сальдо 1С уже включает проведённые платежи, авансы и корректировки. Нельзя вычитать их повторно.
- Без данных о зачёте платежей из 1С нельзя достоверно пометить каждый входящий документ полностью или частично оплаченным.
- Приложение не отправляет платежи в банк и не имеет корпоративной авторизации и серверного аудита.
- **Не размещайте** реальные XLSX/CSV, реквизиты и коммерческие суммы в публичном GitHub.

## Автоматический выпуск

Workflow `.github/workflows/offline-release.yml` собирает и тестирует приложение, создаёт переносимый ZIP и SHA-256. В Pull Request архив доступен как **Actions artifact** (без публикации релиза). После изменений в `main` или ручного запуска Workflow публикуется новая тестовая версия в **Releases**. Старые версии остаются в списке.

Разработчикам: `npm test` — сборка и синтетические тесты. Проверка на реальной ведомости проводится локально, без её загрузки в GitHub.

Если публикация версий не проходит из-за прав, владелец репозитория должен проверить **Settings → Actions → General → Workflow permissions**, разрешив действиям запись в репозиторий.

## Исправление запуска офлайн-версии

Релизы `v0.4.0-preview.1` и `v0.4.0-preview.2` содержат ошибку сборки: в `assets/ui.js` отсутствовал шаблон страницы. На Windows приложение оставалось на экране «Загрузка приложения…». Используйте **новейший** релиз выше по списку. Начиная с исправленной сборки `src/shell/template.js` включается в `assets/ui.js`, а тест запуска проверяет создание разделов и наличие графических ресурсов.

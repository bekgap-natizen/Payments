# ВОЛМАКС — Платежи поставщикам

Локальный прототип учёта и согласования платежей поставщикам **без отправки в банк**. Приложение использует клиентские Excel-выгрузки 1С и хранит результаты **только в браузере**.

> **Важно:** это управленческий прототип, а не интеграция с 1С, бухгалтерская система или многопользовательский сервис. Подтверждение «оплачено» — ручная отметка, не банковская транзакция.

## Скачать готовую версию без сборки

**[Готовые версии для скачивания — GitHub Releases](https://github.com/bekgap-natizen/Payments/releases)**. Откройте нужную версию, в **Assets** скачайте `VOLMAX-Payments-Offline.zip`, распакуйте архив и откройте `index.html`. Устанавливать Node.js не нужно.

Подробная инструкция и ограничения — [docs/RELEASES.md](docs/RELEASES.md). Не путайте готовую сборку с архивами **Source code**, которые GitHub добавляет автоматически.

## Быстрый запуск

Сначала выполните `npm run build`, затем откройте `dist/index.html` в Chrome/Edge либо запустите локальный HTTP-сервер:

```bash
npm run serve
# http://localhost:8080/
```

Приложение не требует Node, npm и интернет-соединения для основной работы. Все JS и CSS — отдельные файлы, браузер загружает их последовательно через `defer`.

## Как работать

1. **Обновить данные 1С** (внизу меню): загрузите XLSX с листом `TDSheet` и укажите дату среза.
2. При первом запуске в разделе **Поставщики** включите действующих контрагентов по каждой организации и задайте отсрочку. Настройки сохраняются.
3. **Платежи на дату** открываются после импорта: виден весь долг, наступившие сроки и автоматически выбранная сумма. При необходимости измените галочки и суммы.
4. Нажмите **Подтвердить и выгрузить Excel**. Подтверждение распространяется на весь выбранный реестр независимо от фильтра; спорные суммы исключаются.
5. Первый лист Excel — компактный платёжный реестр по поставщикам с итогами; остальные листы — общий долг, документы и сверка.

Автоматический выбор — только черновик, не факт оплаты. Локальные отметки не отправляют платежи в банк. Ручные решения сохраняются. Подробнее: [аудит UX](docs/UX_AUDIT.md).


## Структура кода

Исходники разделены **по ответственности**. Файлы с числовыми префиксами — части отдельных функциональных модулей; воспроизводимая сборка объединяет их по группам, чтобы сохранить совместимость со старым локальным приложением без внешних библиотек.

```text
src/core/00-values.js            денежные значения, даты и ключи
src/core/10-xml.js               парсинг XML строк и ссылок 1С
src/core/20-ledger.js            группировка организация/поставщик/документ
src/core/30-reconciliation.js    контроль итоговых сальдо
src/core/40-allocation.js        расчётная модель остатка (НЕ факт зачёта)
src/core/50-analysis.js          расчет на дату и статусы
src/core/60-xlsx.js              чтение ZIP/XLSX 1С
src/core/99-api.js               публичный интерфейс ядра
src/export/                      генерация четырехлистной книги XLSX
src/ui/                          модели экранов, взаимодействия и хранение в браузере
src/shell/template.js            фирменная оболочка (источник сборки UI)
src/styles/                       оформление ВОЛМАКС
assets/volmax-mark.png           фирменный знак
scripts/build.mjs               воспроизводимая сборка в dist/
tests/                           синтетические автоматические тесты
```

Для запуска исходники сначала собираются:

```bash
npm run build
npm run serve
# http://localhost:8080
```

Для офлайн-запуска без сервера откройте **`dist/index.html`** после сборки. Файлы `dist` являются артефактами сборки и не должны вручную редактироваться.

## Тестирование

```bash
node --test tests/*.test.cjs
```

Тесты используют искусственные суммы и контрагентов. Реальные ведомости 1С **не включены** в публичный репозиторий.

## Ограничения

- Конечное сальдо поставщика в 1С **уже содержит прошлые оплаты, авансы и корректировки**. Повторно вычитать их нельзя.
- Исходная ведомость не содержит надёжных связок всех зачётов платежей с входящими накладными. Точные статусы отдельных документов без дополнительных данных из 1С неизвестны; верхнюю оценку суммы к оплате нельзя выдавать за подтверждённый долг по каждому счёту.
- Даты входящих документов и частичные платежи требуют ручной сверки; при несоответствии контрольных сумм приложение предупреждает.
- Индексация снапшотов привязана к дате; повторное чтение того же файла не должно увеличивать остатки.
- LocalStorage/IndexedDB не имеют доступа по ролям, аудита корпоративных пользователей и серверной защиты. Не использовать в качестве единственного реестра платежных обязательств.
- Репозиторий публичный: **не добавляйте** реальные выгрузки 1С, ИНН, банковские реквизиты, персональные данные и коммерческие суммы.

Подробности — в `docs/ARCHITECTURE.md` и `docs/DATA_CONTRACT.md`.
